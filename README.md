# PhraseNest

RedditやEngooなどで読んだ英語を、その場で調べて保存し、PC・スマホで復習する個人向け英語学習アプリです。

PCではChrome拡張機能で英文を取り込み、スマホでは公開ページで復習する使い方を中心にしています。英文を自分で入力・貼り付けて保存することもできます。

- [公開ページを開く](https://phrasenest-reddit-english.uchimaruyukihiro.chatgpt.site)
- [GitHubの作業履歴](https://github.com/marusa77/LEprog/commits/main/)
- 対応ブラウザー：PC版Chrome（拡張機能は0.9.4、Chrome 138以降）
- 保存先：Supabase。Googleログインした利用者ごとに記録を分けます。

## 主な機能

| 入口 | できること |
| --- | --- |
| Chromeの翻訳小窓 | 選択した英文の翻訳、語句候補の表示、訳・メモ・語句の保存、英文・質問文のコピー |
| 入力して保存 | 英文と自分で用意した訳の登録、必要なときだけ英日・日英翻訳 |
| 今日の復習 | 単語・熟語の意味、コアイメージ、例文の確認と復習記録 |
| 保存内容 | 英文・語句・学習メモの一覧、検索、編集・追記、英文の重み付きシャッフルと復習 |
| メニュー | 英作文の練習、未整理分の書き出しと確認、設定 |

主な移動先は「入力して保存」「今日の復習」「保存内容」「メニュー」の4つです。保存内容では、英文・単語／熟語・学習メモを切り替えられます。

## PCで英文を取り込む

1. Reddit・EngooなどのWebページで英文を選択します。
2. `Ctrl + Shift + Y` を押すと、ページ内にPhraseNestの小窓が開きます。
3. 訳やメモを確認・編集し、保存したい語句にチェックします。
4. 「英文と語句を保存」を押します。

サイトを一つずつ登録する必要はありません。呼び出したタブにだけ一時的にアクセスし、全サイトを常時読み取る方式ではありません。元ページのURL・タイトルも保存します。

英文を選択していないときも、同じショートカットでメニューを開けます。Chrome右上のPhraseNestアイコンから「このページでPhraseNestを開く」、保存内容・復習ページへの移動もできます。ショートカットは `chrome://extensions/shortcuts` で変更できます。

Chromeの設定ページ・ウェブストア、画像内の文字、別サイトの埋め込み枠などは取り込み対象外です。スマホ版Redditアプリへの拡張機能の組み込みには対応していません。

### コピーして外部AIに質問する

- 「英文をコピー」：元の英文だけをコピーします。
- 「質問文をコピー」：英文と、意味・重要な語句・コアイメージの説明を頼む指示文をコピーします。
- 語句の「質問をコピー」：その語句と元の英文をまとめた質問文をコピーします。

ChatGPTなどへ自分で貼り付ける方式です。コピーではAI・翻訳APIを呼ばず、保存データも変更しません。自動コピーが失敗した場合は、手動コピー用の欄が表示されます。

### 小窓の表示と保存の注意

四隅のドラッグでサイズを調整できます。通常の最小サイズは400×400pxで、小さな画面では画面内に収まる大きさを優先します。「ワイド」で英文と訳を左右に並べられます。

メニューから文字サイズ・サイズリセットを操作できます。位置・サイズ・文字サイズは、このPCのChromeに記憶します。サイズリセットでは訳やメモを消しません。×で閉じられ、Escはメニューが開いていればメニューを、それ以外では小窓を閉じます。

訳・メモは自動保存ではありません。「未保存」「保存済み」「保存後の変更あり」を確認してください。小窓で保存後に編集して再保存すると、別の英文記録が追加されます。既存の英文を修正する場合は「保存内容 → 英文 → 編集」を使います。

## 英文の並び替えと復習

「保存内容 → 英文」で、次の並び順を選べます。

- 最新順：最近保存した英文を探すための順番。
- ランダム：保存済みの英文全体を混ぜる順番。
- 復習シャッフル：未復習・最後の復習から時間がたった英文を出やすくする順番。

英文ごとの「復習の出やすさ」は「少なめ・通常・多め」から選びます。少なめは、すでに理解できる英文や似た英文を十分読んだときに使えます。完全には除外せず、どの英文にも出番を残します。設定変更やメモの編集では現在の並びを動かさず、次のシャッフルから反映します。

「英文を10件復習」では、5・10・20件から件数を選び、全英文から重み付きで選んだ英文を重複なしで1件ずつ読み直せます。

1. 英文を読み、必要なら「訳・メモを見る」を押します。
2. 「読み直した」で復習日時・回数を保存し、次の英文へ進みます。
3. 「今回はスキップ」では復習記録を付けません。

保存日・編集日は復習日として扱いません。通信失敗後に同じ操作を再試行しても二重に数えない仕組みがあります。英文の復習だけで、関連する単語を「覚えた」へ変更しません。

履歴・出やすさはPCとスマホで共通です。途中の位置はページ内の画面切り替えでは保持しますが、ページを再読み込みすると新しい回になります。

この機能には [0005_sentence_study.sql](supabase/migrations/0005_sentence_study.sql) の実行が必要です。未実行でも最新順・ランダム・従来の編集は使え、新機能には準備の案内が出ます。

## 単語・コアイメージ・学習メモ

単語・熟語には、意味・コアイメージ・自由メモを保存できます。「未学習・学習中・覚えた」の状態と、見つけた回数も確認できます。

同じ語句を英文と一緒に再登録した場合は、語句の記録を重複させず、登場回数・重要度を増やします。英文そのものは別の記録として保存します。

- 「追記」：元の説明を残し、区切り線と【追記】を付けて下に追加します。空欄や同じ説明は追加しません。
- 「編集」：現在の欄全体を修正します。追記した説明を直す場合にも使います。

説明だけの追記では、登場回数・学習状態・復習予定を変えません。同じ語句への再登録時にも説明を追記するには、0004のSQLが必要です。[追記の準備・確認方法](docs/vocabulary-append-guide.md)を参照してください。

「学習メモ」ではコアイメージ・語句メモ・英文メモを一覧で確認できます。保存内容全体の検索、文字サイズ切り替え、語句の状態・メモあり・登場回数による絞り込みにも対応しています。

## 自分で英文と訳を入力する

「入力して保存」はPC・スマホで使えます。英文と日本語訳を自分で入力・貼り付け、使う場面のメモ、入手元、任意の参照URL、必要な語句も登録できます。

「英語を日本語に翻訳」「日本語を英語に翻訳」を押したときだけGoogle翻訳を使います。保存ボタンでは翻訳もAIも呼びません。語句の意味は手入力です。

保存に成功したときだけ入力欄を空にし、続けて別の英文を登録できます。失敗時は入力を残します。画面切り替えでは下書きを保持しますが、ページ再読み込み後の自動復元には対応していません。

## APIを使わない英作文の練習

「メニュー → 英作文の練習」から開きます。

1. 保存済みの表現を1〜3個選び、用意されたお題で2〜4文を書きます。
2. 「作文と指示文をコピー」でChatGPTなどへ自分で貼り付けます。
3. 返ってきた添削・修正文をアプリに貼り付けて保存します。

表現に合うお題が欲しい場合は「お題作成用の指示文をコピー」も使えます。AIへ渡す参考情報は選択した表現に絞り、意味は各250文字・コアイメージは各600文字までに制限します。

作文は入手元「英作文」として保存します。お題・対象表現・添削は区切り付きのメモに残し、保存後の添削追加は同じ記録を更新します。元の語句の説明・登場回数・復習予定は変えません。日本語訳は任意です。

この画面からAI・翻訳APIは呼びません。ただし、外部AIへ貼り付けたときはそのサービスの利用枠を使います。下書きは自動保存ではありません。

## 定期整理と学習記録カレンダー

「メニュー → 整理」では、未整理・追加編集分だけを件数・文字数の上限付きでJSONに書き出せます。Codexなどへ渡し、返ってきた結果JSONを読み込み、候補を採用・見送りしてから保存する方式です。元のメモを直接書き換えず、表示されるトークン数は目安で、実際の消費量を保証するものではありません。[整理のルールと結果形式](docs/organization-guide.md)を参照してください。

「今日の復習」には、最近8週間の学習記録カレンダーがあります。日本時間で、英文保存件数と同じ日に復習した語句数（重複を除く）を集計します。「忘れた」も学習として数えます。

現在、カレンダーには新しい「英文を1件ずつ読み直す」機能の復習回数は加算していません。保存内容・語句の復習履歴を削除すると、該当する集計も減ります。

## 翻訳・費用・現在の制限

- Google Cloud Translationを優先し、アプリ内の上限は利用者ごとに月450,000文字です。英文と語句候補などの翻訳分を合計します。
- 月の集計はSupabase側の暦月です。使い始めてから30日ごとの更新ではなく、月の境界はデータベースのタイムゾーンに従います。
- 拡張機能では、Google翻訳が利用できないときにChrome内蔵翻訳を試します。端末での利用可否や言語データの準備状況によっては使えません。
- 入力画面の翻訳が失敗した場合も、自分で訳を入力して保存できます。
- 復習・編集・追記・シャッフル・コピー・整理用JSONの書き出しはAI・翻訳APIを呼びません。クラウド保存や一覧取得ではSupabaseへ通信します。
- 「AI解説」の入口とサーバー側処理はありますが、APIキー・利用可能なモデルなどの別途設定が必要です。このREADMEはAPI解説が本番で利用できることを保証するものではありません。

アプリ内の上限は、GoogleやSupabaseなどの請求全体を止める仕組みではありません。完全無料を保証するものではなく、各サービスの設定・利用量に応じた確認が必要です。

## セットアップ

### Supabaseを準備する

新しく始める場合は、Supabaseプロジェクトを作成し、SQL Editorで次のファイルを番号順に実行します。

| SQL | 追加される仕組み |
| --- | --- |
| [0001](supabase/migrations/0001_initial_schema.sql) | 基本の保存データ、利用者別アクセス制限、語句の復習・利用量管理 |
| [0002](supabase/migrations/0002_core_image_notes.sql) | コアイメージの保存 |
| [0003](supabase/migrations/0003_organization_workflow.sql) | 未整理管理・整理候補の反映 |
| [0004](supabase/migrations/0004_append_vocabulary_details.sql) | 語句の説明の追記 |
| [0005](supabase/migrations/0005_sentence_study.sql) | 英文の出やすさ・復習履歴 |

既存のプロジェクトでは未実行の追加SQLだけを実行してください。0001は新規作成用なので、既存テーブルに実行し直さないでください。ファイルをGitHubへ送ったり公開ページを更新したりしても、SupabaseのSQLは自動では実行されません。

1. SupabaseのAuthenticationでGoogleログインを有効にし、Google側の認証設定を行います。
2. SupabaseのURL Configurationで、使う公開ページ・ローカルページ・拡張機能のRedirect URL（ログイン後に戻る場所）を許可します。
3. Webページの初回接続画面にProject URLとPublishable keyを入力します。同じGoogleアカウントでログインするとPC・スマホで同じ保存内容を使えます。

Publishable keyと秘密鍵は別物です。Google翻訳・AIのAPIキーやSupabaseの`service_role`／秘密鍵を、README・GitHub・公開ページ・拡張機能に入れないでください。

翻訳を使う場合はGoogle Cloud Translationを有効にし、SupabaseのEdge FunctionのSecretに`GOOGLE_TRANSLATE_API_KEY`を設定して、`translate`をデプロイします。API解説を使う場合だけ`OPENAI_API_KEY`の設定と`explain`のデプロイ・モデル設定を行います。手動で英文・訳を保存するだけなら、翻訳APIは必要ありません。

### Chrome拡張機能を読み込む

1. このリポジトリをダウンロードまたは取得します。
2. Chromeの`chrome://extensions`を開き、デベロッパーモードをオンにします。
3. 「パッケージ化されていない拡張機能を読み込む」で`extension`フォルダーを選びます。
4. 設定画面にSupabaseのProject URLとPublishable keyを入力します。
5. 設定画面に表示される拡張機能用Redirect URLをSupabaseで許可し、Googleでログインします。

Chromeウェブストアには未公開です。別のPCでも同じ手順で読み込めますが、拡張機能のIDが変わる場合があるため、そのPCで表示されたRedirect URLも追加します。通常はログイン状態を保持しますが、期限切れなどで再ログインが必要になる場合があります。

拡張機能を更新したら、`chrome://extensions`でPhraseNestを再読み込みし、利用中のWebページも再読み込みしてください。公開Webページの更新と拡張機能の更新は別です。

### 開発用にWebページを動かす

Node.js 22.13以降を使用します。プロジェクトのフォルダーで実行してください。

```powershell
npm install
npm run dev
```

表示されたローカルURLを開きます。Supabaseの接続情報は初回画面で入力するか、`.env.example`を参考に`.env.local`へ公開用の2項目を設定します。ローカルでGoogleログインする場合は、そのローカルURLもSupabaseのRedirect URLsに追加します。`.env.local`はGitHubへ送らない設定です。

```powershell
npm test
```

ビルドと自動テストを実行します。重み付きシャッフル、保存失敗時の入力保持、通信再試行の扱い、コピーなどを確認します。自動テストだけでは、実際のGoogle認証・翻訳サービス・SupabaseへのSQL適用は検証できません。

## ファイルの構成

- `app/`：PC・スマホ用のWeb画面とSupabaseへの接続処理。
- `app/sentence-study.tsx`：英文一覧・1件ずつの復習画面。
- `app/sentence-study-data.ts`：英文の出やすさとシャッフルの計算。
- `extension/`：PC版Chromeの翻訳小窓・設定・起動処理。
- `extension/common-expressions.js`：よく使う熟語・句動詞の候補一覧。
- `extension/conversation-patterns.js`：会話の定型表現の候補一覧。
- `supabase/migrations/`：SQL Editorで実行する保存データ・処理の設定。
- `supabase/functions/`：Google翻訳・任意のAPI解説のサーバー側処理。
- `docs/`：整理と語句の追記のガイド。
- `tests/`：自動テスト。

## GitHubと公開ページの更新

Gitのコミットは「変更をまとめた作業記録」です。手元で記録しただけではGitHubへ送られません。GitHubへの送信（push）と、公開サイトへの反映（デプロイ）は別の操作です。Supabaseの追加SQLの実行も別です。

例えばREADMEだけを変更した場合は、次のように記録・送信します。

```powershell
git status
git add README.md
git commit -m "docs: update PhraseNest README"
git push origin main
```

コードを変更した場合は、その変更ファイルも確認してコミットに含めます。APIキーや個人の学習JSONは含めないでください。

GitHubのContributionsへの反映には、コミットのメールアドレスがGitHubアカウントに紐づいていること、通常のリポジトリの既定ブランチなどにコミットがあることが必要です。送信後の表示には最大24時間かかる場合があります。[GitHub公式の反映条件](https://docs.github.com/en/account-and-profile/reference/profile-contributions-reference)、[表示されない場合の確認方法](https://docs.github.com/en/account-and-profile/how-tos/contribution-settings/troubleshooting-missing-contributions)を参照してください。カレンダーはコミットなどの記録であり、作業時間そのものを測るものではありません。
